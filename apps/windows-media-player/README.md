# Windows Media Player — проєкт (робоча назва: ZillaPlayer)

> **Статус: P1/P2 / джерельний код прототипу.** Є нативний інтерфейс Rust + Slint, код локального відтворення, багатосмуговий DSP та сканування папок в окремому підпроцесі. **Компіляцію й відтворення на Windows ще не перевірено.** 32-смуговий FFT-спектроаналізатор тепер підключений у вихідному коді; Downloader Alpha у вихідному коді; Windows/network test pending. Назва продукту попередня.

Ця папка ізольована в гілці `apps/windows-media-player`. Гілка `main` залишається універсальним Appbootstrap. Ми свідомо **не** переносимо специфічні правила плеєра у головний шаблон.

## P5 — Downloader Alpha: реалізовано у вихідному коді

- Вкладка **Завантаження** більше не декоративна: черга до 64 завдань, кнопки повтору/скасування, фонове виконання через yt-dlp.
- **MP3 320k**, оригінальна аудіодоріжка, **відео до 1440p QHD (умовно «2K»)**, 1080p і найкраща якість, FFmpeg **склеює відео й аудіо у MKV**.
- Режим плейлиста (до 200 позицій), збереження історії на диску, перевірка наявності yt-dlp/FFmpeg/Deno.
- Завершені аудіофайли додаються до локальної бібліотеки. Відео залишається у папці завантаження.
- **Це код alpha, реальна робота з сайтами ще потребує перевірки**, а інструменти потрібно встановити окремо. Без обходу DRM, cookies чи несанкціонованих завантажень.
- [Інструкція з встановлення / профілі / обмеження](docs/DOWNLOADER_ALPHA.md).

## Ідея продукту

Легкий нативний музичний плеєр для Windows 10/11 (x64, пізніше ARM64) у дусі AIMP/Winamp: локальні аудіофайли, потужний еквалайзер та DSP, візуалізації, швидкий каталог і плейлисти, модульність, а також **окремий** менеджер завантажень на базі yt-dlp з підтримкою допустимих джерел та власних/дозволених користувачеві медіа.

**Не робимо одразу:** браузер, відеоредактор, системний еквалайзер для всіх програм, DRM-обхід, власні екстрактори тисяч сайтів, VST-хост, мобільний застосунок чи хмарний сервіс.

## Ключове технічне рішення

- Основна мова: **Rust** (кандидат, приймаємо для прототипу).
- GUI: **Slint** (кандидат; пройти технічний + ліцензійний spike).
- Audio output (P1 alpha): **Rodio 0.21.1 → CPAL** → WASAPI shared mode на Windows. Далі дослідимо прямий CPAL із власним DSP callback.
- Decode: **Symphonia через Rodio**, MP3/FLAC/WAV/OGG/M4A (фактичні файли ще потрібно протестувати).
- DSP: 31-смуговий Biquad EQ (усі 31 частота керуються з інтерфейсу; горизонтальна прокрутка), бас, тембр, loudness, bypass. Декодер і розрахунок коефіцієнтів уже винесені з аудіошляху **в коді**, але Windows-обробка, інші виклики Rodio/CPAL та фактична real-time безпека ще не перевірені.
- Library: сканування у Windows-підпроцесі, JSONL IPC та список до 50 тис. треків. **Додано асинхронне збереження й відновлення черги** в `%APPDATA%\\ZillaPlayer\\session-v1.json`; повна SQLite-бібліотека та метадані ще попереду.
- Downloads: **реалізований фоновий супервізор yt-dlp**, FFmpeg для MKV/MP3, постійна черга й імпорт аудіо; Deno/EJS потрібні для повноцінної підтримки деяких джерел. Якість і права залежать від конкретного сайту.
- Плагіни: власні вбудовані інтерфейси на старті, розширення зовнішніми адаптерами після визначення ABI / безпеки.

Усі залежності й версії треба зафіксувати після proof-of-concept; список тут **не є затвердженим Cargo.lock**.

## Останній інженерний крок

- **Повний еквалайзер:** 31 частотний повзунок з прямою відповідністю `BAND_HZ` Rust DSP, горизонтальний `ScrollView` для різних розмірів вікна.
- **Decoder timeout cancellation:** `prepare()` тепер надсилає прапорець скасування дочірньому decoder-worker при помилці/тайм-ауті; тести перевіряють скасування покинутої ініціалізації.
- **UI contract validation:** `python tools/check_ui_contract.py` перевіряє частоти, кількість смуг і callback-маршрут ще до Windows Cargo CI.
- **Build evidence:** Windows Actions завантажує resolved `Cargo.lock`, показує версії `rustc/cargo`; без реального запуску зелений статус **не заявляємо**.

## Нове: справжня FFT-візуалізація

- Перший функціональний **32-band FFT**: 2048 семплів, Hann-window, RustFFT 6.4.1, 32 логарифмічні частотні смуги.
- Незалежний потік обчислень отримує лише копії семплів із обмеженого SPSC-буфера. Коли аналізатор запізнюється, дані **відкидаються**, а відтворення не чекає.
- Slint отримує готові дані до 20 FPS. При переході на Library/Downloads оновлення моделі призупиняється; Pause/Stop приховують застарілі смуги.
- Тести для синусоїди 1 кГц, тиші, захисту від невірних значень і застарілих поколінь задач.
- [Специфікація FFT](docs/LIVE_VISUALIZER.md). **Windows-збірка і реальна частота кадрів ще не підтверджені.**

## Нове: збереження черги та живий рівень аудіо

- **Session I/O worker:** черга треків і вибрана позиція зберігаються між запусками без дискового I/O у Slint. Запис із резервною копією, відновлення пошкодженого основного JSON, ліміт 50 тис. записів.
- **PCM Peak Meter:** до інтерфейсу підключено **справжній показник рівня аудіосемплів**, зчитаний із буфера відтворення. Окремо з’явився **живий 32-смуговий FFT-спектроаналізатор** з аналізом у фоновому потоці.
- **Rodio typing:** виправлено тип декодера для `Decoder<BufReader<File>>` відповідно до API Rodio.
- Перевірки коректності включають Unicode-сесію, відновлення з backup і тест пікового рівня PCM (тести написані, але ще не виконані на Windows).

## Функції цієї ітерації

- Виправлено життєвий цикл сканера: контроль процесу через `try_wait()`, окремий reader stdout, cancellation + `kill/wait` і завершення supervisor-потоків під час виходу.
- Коефіцієнти 31-смугового EQ тепер створюються у **керівному аудіопотоці** та публікуються через атомарні snapshots, а не обчислюються під час кожного оновлення в аудіозмішуванні.
- **Audio Engine 2.0:** декодування Rodio/Symphonia винесене в окремий decoder worker. Він заповнює обмежений SPSC PCM ring (`src/pcm_ring.rs`), а аудіовихід отримує готові семпли через `BufferedPcmSource` без disk I/O або decode у `next()`. Seek запускає новий decoder worker на цільовій позиції, старий скасовується. Є лічильник нестачі PCM-буфера та тест із самостійно згенерованим WAV.
- Додано **Import M3U/M3U8** і **Save M3U8** на сторінці Library. Файловий діалог відкривається за дією користувача; читання/запис виконується в окремому потоці. Підтримуються UTF-8, `#EXTINF`, вкладені/відносні шляхи.
- У Windows CI додано smoke-тест дочірнього режиму сканера, а до Rust-тестів — Unicode-плейлисти й одночасні зміни параметрів EQ.

**Збірку на Windows та реальне прослуховування ще не підтверджено.** Зверни увагу: хоча власний Rodio source більше не декодує під час аудіозмішування, реальна **робота на Windows, затримки та відсутність underruns не підтверджені**. Наступні пріоритети: Windows build, вимірювання, об'єднання rapid-seek команд.

## Швидка перевірка збірки Windows

```powershell
cd apps/windows-media-player
pwsh -File tools/verify-windows.ps1
```

Скрипт виконує `cargo check`, `cargo test`, `cargo build --release`, перевіряє наявність EXE та підказує зафіксувати `Cargo.lock`. Він **ще не був запущений у Windows-середовищі цієї розмови**, тому результат компіляції невідомий.

## Запуск Windows alpha-прототипу

Встановіть Rust stable (MSVC), а також Visual Studio Build Tools / Desktop development with C++.

```powershell
cd apps/windows-media-player
cargo run
```

В UI кнопка **Open File** відкриває системний діалог, далі Rust надсилає декодований звук через CPAL/WASAPI; є Play/Pause/Stop/Seek/Volume. **Це alpha-код, а не підтверджений working build.** Є 31-смуговий DSP-процесор і керування басом/тембром/гучністю, сканування папок через кнопку Folder. 32-смуговий FFT працює у вихідному коді через незалежний аналізатор, але ще не перевірений на Windows; downloader поки прототип інтерфейсу. Докладніше: [IMPLEMENTATION_STATUS.md](docs/IMPLEMENTATION_STATUS.md), [DEVELOPMENT_NOTES.md](docs/DEVELOPMENT_NOTES.md).
